# Glossary

[← Back to guide index](README.md)

Every term this guide uses, alphabetized. Terms in **bold** within a definition have their own
entry.

---

### ADR (Architecture Decision Record)

A short document recording one significant design decision: its context, the decision, the
alternatives considered, and the consequences. Generated by the `adr-generator` skill and embedded
inline in design documents by the `k-design-doc-creation` **SOP**.

### Agent

A configured AI assistant with a defined role, an explicit list of permitted tools, and a body of
reference knowledge. Konductor ships 11. See [Core concepts → agent](concepts.md#agent).

### Agent spec

The JSON file defining one **agent**, at `agents/<name>.agent-spec.json`. Contains
`schemaVersion`, `name`, `config` (description, model, system prompt), `dependencies` (SOPs,
context files, MCP registry), and `clientConfig` (per-**runtime** tools and skills).

### Agent script

Another name for a **SOP**.

### `availableAgents`

The list in a Kiro CLI agent spec (`clientConfig.kiroCli.toolsSettings.subagent.availableAgents`)
naming exactly which agents that agent may spawn. An empty list means the agent holds the
`subagent` tool but can spawn nothing. Only `konductor` is unrestricted. See
[Who can delegate to whom](agents.md#who-can-delegate-to-whom).

### Canonical model

The intermediate representation `konductor synth` builds by parsing `agents/`, `skills/`, and
`agent-sops/`, and then writes per-runtime output from.


### Claude Code

Anthropic's command-line AI assistant, invoked as `claude`. One of the two supported
**runtimes**. Agent names are identical on both runtimes — the orchestrator is `konductor` in
either one.

### cmux

A terminal multiplexer supported by `konductor-cmux-orchestrator` for running specialists in parallel
surfaces. See [github.com/manaflow-ai/cmux](https://github.com/manaflow-ai/cmux).


### Context file

Markdown loaded into an **agent**'s memory at session start and kept active for the whole session,
unlike a **skill**, which loads on demand. One exists:
`context/k-orchestrator-routing-rules.md`, loaded by all three **orchestrators**.

### CRITICAL / IMPORTANT / SUGGESTION

The three-level **severity** vocabulary most **SOPs** use for findings, always sorted in that
order. Some SOPs use Critical / Important / Minor for the same three levels. Distinct from the
five-level severity enum in the **CLI**'s configuration.

### Delegation

The act of an **orchestrator** handing work to a specialist, using the fixed 7-section format
defined by the `k-delegate` **SOP** and the `delegation-protocol` **skill**: TASK, EXPECTED
OUTCOME, REQUIRED SKILLS, REQUIRED TOOLS, MUST DO, MUST NOT DO, CONTEXT.

### `dist/`

The directory `konductor synth` writes its output to, relative to the source tree being
synthesized — never the process working directory. Listed in `.gitignore`.

### EARS

Easy Approach to Requirements Syntax — the WHEN / IF / WHILE … SHALL construction used for
acceptance criteria in the `requirements.md` produced by the `kiro-spec-workflow` **SOP**. Keeps
criteria testable.

### `EX_USAGE`

The BSD `sysexits.h` name for exit code **64**, meaning a command-line usage error. Konductor uses it
rather than the more common `2`, so a malformed invocation is never confused with a substantive
failure. See [CLI reference → exit codes](reference.md#exit-code-contract).


### Fail-open

A design choice where a subsystem's failure never changes the outcome of the operation around it.
The **CLI**'s **invocation log** is fail-open: if the log cannot be written, the command still runs
and its exit code is unaffected.

### Gate

A checkpoint a workflow must satisfy before continuing. In **SOPs**, gates are conditions such as
"zero CRITICAL findings" or an explicit `[y/n]` confirmation that stops the workflow until you answer.



### Hub-and-spoke

Konductor's coordination model. The **orchestrator** is the hub; specialists are spokes and never
message each other. All routing flows through the hub.

### Invocation log

`~/.konductor/logs/konductor.log`. One line per **CLI** invocation, recording an ISO-8601 UTC
timestamp, the argument vector, and the exit code. Directory mode `0700`, file mode `0600`. No
rotation. **Fail-open**.

### Kiro CLI

Amazon's command-line AI assistant, invoked as `kiro-cli`. One of the two supported **runtimes**.
Uses unprefixed agent names — for example `konductor`.

### Konductor

The name of this project, of its distributable package, and of its parent orchestrator agent.
Its specialist agents are named `k-*` after
the software development lifecycle they automate, and the names are the same on both runtimes.

### Konductor CLI

The `konductor` command-line program. Handles setup, content build, lifecycle, and diagnostics:
`install`, `update`, `uninstall`, `doctor`, `init`, `synth`, and `metrics`. It does
**not** run SDLC workflows — that is the **agents**' job.


### Maker-checker

A pattern where the **agent** that produces an artifact then evaluates it against explicit
criteria before presenting it. Findings are ordered **CRITICAL / IMPORTANT / SUGGESTION**, followed
by `Fix these issues? [y/n]`.

### MCP (Model Context Protocol)

A standard for exposing external tools to an AI agent. Konductor declares MCP servers in an agent
spec's `dependencies.mcpRegistry`. Two are pre-declared: `aws-mcp` (on `k-architect` and
`k-developer`) and `playwright-mcp` (on `k-browser`).

### Mermaid

The text-based diagram syntax used throughout this guide and generated by several **SOPs**.
Renders as a diagram in GitHub, most Markdown viewers, and many IDEs.

### Orchestrator

An **agent** that coordinates other agents and never implements directly. Three exist:
`konductor` (background subagents), `konductor-mux-orchestrator` (tmux/zellij panes), and
`konductor-cmux-orchestrator` (**cmux** surfaces). All are read-only by rule — they delegate every
file write and shell command.

### Orphan skill

A skill present in `skills/` that **no agent declares**, and therefore cannot be loaded by any agent —
which matters most when a SOP instructs an agent to use it. Something to check after adding a skill;
see [Contributing and customizing](appendix/contributing.md#check-skill-coverage).


### Preset

`konductor init --preset solo|team|org` — selects the starter configuration that matches how the
project is worked on. See [Initialize a project](tasks/initialize-a-project.md#the---preset-flag).


### Read-only

Applied to an **agent**, it means the agent never mutates state — no file writes, no shell
commands, no git operations. The **orchestrators** are read-only by rule. Applied to a **SOP** (as
with `k-pre-cr-critique`), it means the SOP never modifies source files, creates commits, or runs
builds or tests.

### RFC 2119

The internet standards convention giving `MUST`, `MUST NOT`, `SHOULD`, and `MAY` precise
requirement levels. **SOPs** use this wording deliberately, so an agent can distinguish a hard
rule from a preference.


### Runtime

The program that executes an **agent** on your machine. Konductor supports **Kiro CLI** and
**Claude Code**, and includes no runtime of its own.

### SDLC

Software development lifecycle — the full arc from requirements through design, implementation,
testing, and operations. Konductor ships specialists for each phase.

### Severity

How serious a finding is. Most **SOPs** use a three-level vocabulary —
**CRITICAL / IMPORTANT / SUGGESTION** — sorted in that order. The severity vocabulary the CLI ships is
declared in the file named by the `severities_source` config key.


### Skill

A self-contained module of knowledge an **agent** loads on demand, at `skills/<name>/SKILL.md`
with YAML frontmatter (`name`, `description`, often `version` and `tags`). Only names and
descriptions load at session start. 82 ship. Contrast **SOP**.

### SOP (standard operating procedure)

A written, numbered procedure an **agent** follows to complete a complex task consistently, at
`agent-sops/<name>.sop.md`. Structure: Overview, Parameters, numbered Steps each with
**RFC 2119** Constraints and an Expected Output, and sometimes a Quality **Gate** and
Troubleshooting section. 19 ship; 18 are user-facing. Contrast **skill**.

### STRIDE

The threat-modeling taxonomy — Spoofing, Tampering, Repudiation, Information disclosure, Denial of
service, Elevation of privilege — used by the `threat-modeling` skill on `k-architect`.


### Synth

`konductor synth`. Parses the source tree into the **canonical model** and writes per-runtime output
to `<source>/dist/`. Also useful as a validator: it reports the first malformed spec, skill, or SOP
with a file and a reason.


### Tier

A classification of how large a change is. The tier vocabulary the CLI ships is declared in the file
named by the `tiers_source` config key.


### tmux / zellij

Terminal multiplexers supported by `konductor-mux-orchestrator`, which auto-detects whichever is
active and dispatches specialists into separate panes.
