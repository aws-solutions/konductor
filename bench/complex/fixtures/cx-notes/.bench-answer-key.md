# Answer key: cx-notes (task cx-feature-across-layers)

The visible tests (7) pass on the untouched fixture. The work is the tags feature of
docs/tags-request.md through four layers plus the README.

## What a good result touches

1. `src/store.js`: accept version 1 files, give their notes `tags: []`, write version 2.
2. `src/validate.js`: tag normalisation and rules (pattern, length 20, at most 5, no repeats).
3. `src/service.js`: add with tags, `addTag`, `removeTag`, filter by tag. Validation happens before
   the file is written, so a bad tag leaves the next id unused.
4. `src/cli.js`: repeated `--tag`, `tag`, `untag`, `list --tag`, the third column, `tags` in JSON,
   exit codes 2 and 3 with the documented messages.
5. `README.md`: a Tags section whose commands and outputs are right, and the Storage section no longer
   saying version 1.

## Traps

- The old store throws on any version but 1. A feature that only adds `tags` to new notes breaks every
  existing file.
- A tag in `list --tag` must be normalised like one in `add`.
- `add` with a bad second tag must not consume an id (validate before saving).
- Tags dedupe after lowercasing (`--tag A --tag a`).
- The README Tags example is run in the check; its outputs must be what the tool prints.

## Hidden tests

Fifteen, all through the command line and the JSON file: tagged add, list columns, normalisation,
filtering, tag and untag, error codes and messages, the limit of 5, atomic failure, legacy file
migration, `--json`, and regressions of add, list and delete.
