# Answer key: cx-carddemo-batchday (task cx-carddemo-batchday)

The fixture holds five CardDemo COBOL batch programs (posting, interest, the transaction report, the statements and
their called file program), thirteen copybooks, eight sample data files, the rules (`docs/REQUIREMENTS.md`), the
interface (`docs/INTERFACE.md`) and an empty package `carddemo_port`. The work is the whole port: four jobs, four
commands, tests and a README. The untouched fixture fails the hidden tests.

Source: aws-samples/aws-mainframe-modernization-carddemo at commit
59cc6c2fd7ebd7ef7925cad552a01a4b8b6e4d5e (Apache-2.0). `LICENSE` and `NOTICE` name it and say what was changed in data/.

This task extends `cx-carddemo-port` (jobs 1 and 2, kept as they are, same signed rules) with two jobs whose spec is
deliberately thin: the documents give command lines, file names and the DRAFT rules, and the copybooks and the COBOL
give the rest. An agent has to read `CBTRN03C.cbl` and `CBSTM03A.CBL` closely.

## Rules the owner has signed (jobs 1 and 2)

P5, P7, I2, I3, I4 and "no fees" are carried over word for word. Only P5, P7 and I4 differ from the COBOL; I2 and I3
match it. The hidden tests for jobs 1 and 2 are the 70 of `cx-carddemo-port` (the sample golden tests now run on the
new data).

## Where the documents are silent and the COBOL decides (the hidden tests check it)

The page-break count (every line written counts, so pages are 16, then 14 detail lines, and an account total that steps
over a multiple of 20 does not break); the break on a change of card, not account; descriptions cut at 15 and 29 in the
report and at 49 in a statement; the name lines cut at the first blank of each part (no middle name leaves two
blanks, and the HTML name then stops at the first name); the last address line made of the first word of line 3, the
state, the country and the zip; the HTML bank block and table heads; the lookup done only for records in the range.
No GnuCOBOL was available when this was written, so none of these was run on the real programs; each was read from the
source. The `Z(9).99-` edit of a value under 1 is the one place the COBOL picture and R5 differ on purpose.

## Hidden tests

129, run with `node --test hidden/*.test.js`. They start `python3 -m carddemo_port` in the workspace and compare files
byte for byte. Inputs come from `hidden/lib/cd.js` and `hidden/lib/day.js`. The processed timestamp is masked.

| File | Tests | Covers |
|---|---|---|
| `posting.test.js` | 27 | P1 to P13, M1, M2 sign digits |
| `interest.test.js` | 20 | I1 to I9 |
| `input.test.js` | 19 | M3, output directory rules, usage errors |
| `report.test.js` | 28 | R1 to R5, page breaks, lookups, bad input |
| `statements.test.js` | 26 | R5 to R8, text lines, HTML lines, bad input |
| `golden.test.js` | 9 | the four jobs on the sample files, the chain, the books |

`hidden/golden/in` is a copy of `data/`; `hidden/tools/make_sample.py` made `data/` from the upstream files (seeded).
The goldens were written by the reference port. Regenerate: `CARDDEMO_GOLDEN_WRITE=1 node --test hidden/golden.test.js`
in a workspace that holds the reference.

## Limits of this task

- Author and subject share a family (Claude). A non-Claude recheck of the hidden tests, the data and `INTERFACE.md` is open.
- The DRAFT rules are not signed. No score may be used until the owner signs R1 to R8 or changes them.
- The goldens come from the reference port, so they prove agreement with it. The hand-worked lines in `report.test.js` and
  `statements.test.js` (written from the COBOL pictures, in `lib/day.js`) are the independent part.
- Expected length for a strong agent: 40 to 60 minutes is the aim, not a measurement. The reference is about 800 lines; a
  strong agent that reads the two big programs and writes the port plus its tests may well finish in 30 to 45.
