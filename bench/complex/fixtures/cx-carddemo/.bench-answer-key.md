# Answer key: cx-carddemo (task cx-carddemo-port)

The fixture holds two CardDemo COBOL batch jobs (posting, interest), six copybooks, the five sample
data files, the signed-off rules (`docs/REQUIREMENTS.md`), the interface (`docs/INTERFACE.md`) and an
empty package `carddemo_port`. The work is the whole port: two jobs, a command line, tests and a README.
No part of it is in the fixture, so the untouched fixture fails the hidden tests.

Source: aws-samples/aws-mainframe-modernization-carddemo at commit
59cc6c2fd7ebd7ef7925cad552a01a4b8b6e4d5e (Apache-2.0). `LICENSE` and `NOTICE` name it.

## Where the documents and the COBOL disagree

The hidden tests follow the documents. An agent that copies the COBOL fails the first three rows below (P5, P7, I4). I3 and I2 are listed because the documents state them, but the COBOL already does the same (it truncates, with no `ROUNDED`, and it stops when no DEFAULT rate exists), so copying the COBOL passes them.

| Rule | COBOL does | Documents say | Hidden tests that catch it (by name) |
|---|---|---|---|
| P5 over limit | subtracts the (negative) debit, so payments count as charges | payments net against charges | the tests named P5 in `posting.test.js`, and the sample golden (23 rejects) |
| P7 duplicate id | none (a duplicate key stops the job) | reject 104, first one stands | the tests named P7 in `posting.test.js` |
| I3 rounding | truncates (same as the documents) | truncate toward zero | the tests named I3 in `interest.test.js`, and the chain golden. Catches an agent that rounds, not one that copies the COBOL |
| I4 credit balance | would make negative interest | no interest | the test named I4 in `interest.test.js` |
| I2 no DEFAULT rate | stops the job (same as the documents) | stop, write nothing | the tests named I2 in `interest.test.js`. Catches an agent that invents a rate, not one that copies the COBOL |

## Where the rules are silent (accepted either way)

`docs/REQUIREMENTS.md` does not decide these, so the hidden tests accept both behaviours (owner ruling,
2026-11-26: relax where the rules are silent, keep every test, stay strict everywhere else).

| Point | Behaviour A | Behaviour B | How the tests accept both |
|---|---|---|---|
| A positive balance and rate whose interest truncates to 0.00 (I3, I4, I5) | no row (the reference; this is the side that departs from the COBOL) | a row of +0.00 (what the COBOL does: `CBACT04C.cbl` writes a row whenever the rate is not zero) | `cd.dropZeroInterest` drops a +0.00 row only when every other field is the I5 row of its account (type 01, category 0005, source, description, merchant fields, lowest card, timestamp shape), then renumbers the I6 counter; the rest must match exactly. A -0.00 row or a wrong row is kept and fails. The summary count is lowered by the rows dropped. Used by the I3 test and the interest and chain goldens. |
| The sample `tcatbal.txt` ends 49 of its 50 lines with CRLF | read it (the reference splits lines with `splitlines`) | refuse it as bad input, exit 2 | `golden.test.js` checks a refusal is a clean failed run naming `tcatbal.txt line 1`, then repeats the run on the same files with LF lines. |
| Line ends of output files | LF | CRLF | `cd.run` reads output files with CRLF as LF; every other byte still counts. |

The test of these relaxations is `bench/runner/test/cx-carddemo-relax.test.js`.

Other traps: floats (two interest cases come out one cent short with floating point), the order of
checks (P6), a payment tested against the limit like any amount, the interest counter that skips rows
without interest, the lowest card number of an account, accounts without category rows left untouched,
a failed run that leaves no output and no temporary file.

## Hidden tests

70 tests, run with `node --test hidden/*.test.js`. They start `python3 -m carddemo_port` in the
workspace, so they depend on nothing but the command line, the files and the exit codes.
Inputs are built by `hidden/lib/cd.js`; outputs are compared byte for byte. The processed timestamp
(the run clock) is checked for shape and then masked, because a test cannot fix the clock.

| File | Tests | Covers |
|---|---|---|
| `posting.test.js` | 27 | P1 to P13, M1, M2 sign digits |
| `interest.test.js` | 20 | I1 to I9 |
| `input.test.js` | 19 | M3, output directory rules, usage errors, exit codes |
| `golden.test.js` | 4 | both jobs on the 50-account sample, and the chain post then interest |

`hidden/golden/` holds the expected outputs, written by the reference port. To write them again from a
workspace that holds the reference: `CARDDEMO_GOLDEN_WRITE=1 node --test hidden/golden.test.js`.
`hidden/golden/in/` is a copy of the sample files, so a changed `data/` cannot change a hidden result.

## Reference and partials

The reference port (`solutions/cx-carddemo-port`) passes all 70 and has its own 57 unit tests.
Partials (each scores strictly between 0 and 100 percent, with different counts):

- `post-only`: posting works, the `interest` command is missing.
- `cobol-rules`: copies the COBOL where the documents differ (P5, P7, I4), and also rounds half up in I3, which is neither the COBOL (it truncates) nor the documents.
- `no-output-checks`: writes straight into the output directory and accepts a non-empty one.
