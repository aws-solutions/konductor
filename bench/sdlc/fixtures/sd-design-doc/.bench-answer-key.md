# Answer key: sd-design-doc (task sdlc-design-review-gaps)

The deterministic key is in the task's hidden tests (`hidden/gaps.test.js`); this file is for the judge.

## Planted gaps

- G1 (§2, §3): no latency or throughput target. "Checkout stays fast" has no number, though the README gives a peak
  of 40 orders a second.
- G2 (§4): unstated assumption that node clocks agree. Each node compares `expiresAt` with its own clock, and a timer
  per node is lost when the node restarts.
- G3 (§3, §5): no failure mode for the payment provider. A timeout (1 in 500 calls) leaves the order between
  reserved and paid; nothing says whether stock is released, the charge retried or the customer told.
- G4 (§5): `POST /admin/refunds` names no authentication or authorization; anyone who can reach it can refund.
- G5 (§8): no rollout or migration. A new table and new `orders.status` values with no backfill of open orders,
  no order of deploys, no flag and no rollback.
- G6 (§3): the diagram contradicts the text: the text says checkout calls the inventory service through the stock
  cache, the diagram calls `InventoryDB` directly and shows `StockSvc` unused.
- G7 (§4): reservations store email and shipping address with no retention or deletion rule.

## Covered (claiming them missing is a false alarm)

- Idempotency of reserve (§4), rate limiting (§6), monitoring and an alarm with an operator action (§7).
