# probe-qa-orders answer key

Judge-only. Runners must not copy this file into the agent working directory.

Used by two tasks: a review of `test/orders.test.js` (probe-u2-severity-review-qa) and a test plan written from `docs/feature-spec.md` (probe-u1-checker-pass-qa). There are no code changes.

## Planted issues in the tests (review task)

| ID | Issue | Intended severity |
|----|-------|-------------------|
| Q1 | `refund by another customer is rejected` catches the error and asserts nothing, so it passes whether or not the refund is rejected. `requestRefund` ignores `actor`, so any customer can refund any order, and the test hides it. | critical |
| Q2 | No test for rule 1 (a shipped order cannot be cancelled) and none for rule 4 (a refund over 500.00 is `pending-approval`). The error paths and the approval branch are untested. | important |
| Q3 | Money is summed as floating-point numbers with no rounding, and the tests only use amounts that happen to be exact (for example 0.1 times 3 is 0.30000000000000004). A rounding case is missing. | important |
| Q4 | Two tests are named `test 1` and `test 2`, which says nothing about the rule they cover. | suggestion |
| Q5 | Every test builds its order literal by hand; a small helper would remove the repetition. | suggestion |

Other findings are acceptable if they are true (for example, no test that a non-owner cannot cancel, which is part of Q2).

## Spec facts for the test plan task

A good plan covers: cancel allowed in `placed` and `packed`, rejected after shipping (rule 1); owner and support allowed, others rejected (rule 2); refund amount with and without shipping (rule 3); the 500.00 boundary, below, at and above (rule 4); at most one refund per order and idempotent repeat (rule 5); refund before cancel rejected (rule 6); out-of-scope items named as out of scope; test data and expected results per case.

## Severity words

The agent chooses its own scale. The study reads whether the labels are CRITICAL, IMPORTANT and SUGGESTION and in that order; the checks do not.
