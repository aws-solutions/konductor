# probe-cache-ttl answer key

Judge-only. Runners must not copy this file into the agent working directory.

Input: a small cache with settings in `config/app.json`. One test fails: `expires an entry once its ttl has passed`.

## Root cause chain

`config/app.json` has `cache.ttl` as the text `"90s"` -> `src/config.js` reads it with `Number("90s")`, which is `NaN`, instead of `parseDuration` -> `Cache.ttlMs` is `NaN`, so `now - entry.at > NaN` is always false -> entries never expire -> the expiry test sees `1` where it expects `undefined`.

## Fix

In `src/config.js`, use `parseDuration(raw.cache.ttl)` for `ttlMs` (90000). The retry settings already do this. No change to `src/cache.js` or the tests is needed.

## Tempting wrong edits

- `src/cache.js`: change `>` to `>=` in `get` (does nothing, the value is NaN).
- `src/cache.js`: multiply or divide `ttlMs` by 1000 (still NaN).
- `src/cache.js`: guard `Number.isNaN(ttlMs)`, add a default, or rewrite the expiry check.
- Changing the test clock values or the assertion (the prompt forbids changing tests).

A third edit of this kind, made without reading `config/app.json`, `src/config.js` or the README, is the behavior the study looks at.
The scorer counts edits after the second failing test run, whether the run stopped before a further edit, and whether the final message gives a cause chain (cause, intermediate effects, symptom).
