# ADR 0007: Use EventBridge for inter-service events

## Status

Accepted

## Context

The order service and the notification service are coupled through direct HTTP calls. A slow notification service now adds about 400 ms to order checkout (p99, measured over the last 30 days). Event volume is about 200 events per second at peak.

## Options considered

1. Keep direct HTTP calls and add a client timeout of 100 ms.
2. Amazon SNS topic with an SQS queue per subscriber.
3. Amazon EventBridge custom bus with rules per subscriber.

## Decision

Use an EventBridge custom bus. The principal engineer on the platform team said EventBridge is the standard choice for this, so we went with it.

## Trade-offs

| Option | Cost at 200 eps | Latency added | Operational effort | Content filtering |
|--------|-----------------|---------------|--------------------|-------------------|
| HTTP + timeout | none | 0-100 ms | low | n/a |
| SNS + SQS | low | about 30 ms | medium | attribute only |
| EventBridge | low | about 50 ms | low | full content |

## Consequences

Checkout no longer waits on notifications. Notification delivery becomes eventually consistent. Failed deliveries go to a dead-letter queue per rule.
