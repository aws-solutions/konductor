# Answer key: hard-migrate (task hard-migrate-orders)

5 visible tests pass before and after. docs/SCHEMA.md is the contract; the existing `up` is a first attempt.

## Seeded defects in the existing `up`

1. `src/money.js`: `Math.floor(total * 100)`. 19.99 gives 1998; 1.005 gives 100 instead of 101. Needs decimal
   arithmetic on the number as written, rounded half up. `Math.round` alone still gives 100 for 1.005.
2. `src/dates.js`: `new Date(y, m - 1, d).toISOString()` shifts the day in zones ahead of UTC (hidden tests run
   with `TZ=Asia/Tokyo`) and rolls over impossible dates (02/30 becomes 03/01). Needs a calendar check and string
   handling with no `Date` in local time (the comment "dates are handled in local time" is wrong).
3. `src/address.js`: `split(', ')` into exactly three parts; a street with a comma loses data; the region regexp
   is unanchored so ZIP+4 loses its suffix and lowercase or malformed tails pass.
4. `src/schema.js`: `...extra` is spread last, so an input `"schema":1` overwrites `"schema":2`. No validation:
   bad values become `NaN`/`undefined` instead of a rejected record with a reason.
5. `src/migrate.js`: `copyFileSync` overwrites the backup on every run, so a second `up` destroys the only copy
   of the original. v2 records are converted again (garbage). Blank lines and CRLF are rejected or leak `\r`
   into `raw`. Writes are not atomic. No state file, no `--dry-run`, no `--force`, `down` throws.

## Traps

- Rejected lines stay in the file; `rejects.jsonl` is removed when nothing is rejected.
- An up that changes nothing must not rewrite files (bytes and backup identical) but a changed file with an
  existing backup must keep the old backup and update the state hash.
- `down` must compare the file hash to `resultSha256`, exit 3 on mismatch, and `--force` overrides.
- Dedupe: a duplicate id of an earlier record is rejected even if the earlier record was rejected itself.

## Intended resolution

Rewrite the converters with validation, `convert()` with reasons in the documented order, atomic writes with a
state file, `down`, flags, exit codes via an error class. Reference: `tasks/solutions/hard-migrate-orders/`.
