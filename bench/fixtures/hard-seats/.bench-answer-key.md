# Answer key: hard-seats (task hard-seat-holds)

The visible tests (7) pass on the untouched fixture. They call `book` one at a time, so they cannot see the
concurrency defects. The hidden tests fire many calls at once.

## Seeded defects in `src/booking.js`

1. Lost update: `book` reads the free seat count, awaits the charge and then writes `left - 1` from the earlier
   read. Calls that run at once all read the same count, so 200 calls on 10 seats confirm 200 bookings.
2. Duplicate check races too: two calls by one user both read "no booking" before either writes one.
3. No timeout: a charge that never settles holds the call forever. `timeoutMs` is accepted and never used.
4. No cancellation: the caller's `signal` is ignored, and no signal is passed to `payments.charge`, so a timed
   out or aborted booking leaves the charge running.
5. `notifier.send(booking)` is neither awaited nor caught. A rejected send is an unhandled rejection, and a send
   that throws synchronously fails a booking that was already charged. `notifyFailures` never changes.
6. A seat is taken only after the charge, so `remaining` does not count calls still paying (spec rule 3).

## Traps

- `docs/OPERATIONS.md` says one process per host, so an in-memory lock or queue per event is enough. A
  distributed lock is not asked for.
- Taking the seat under a lock and then holding the lock across the charge serialises every booking of an event.
  It passes the tests but makes each event one booking at a time; the intended fix holds the seat, not the lock.
- A timeout built with `setTimeout` that is never cleared keeps the process alive for `timeoutMs` after every
  fast charge.

## Intended resolution

Reserve the seat and the user's hold in one atomic step (a per-event lock or queue around the read and write of
the store), charge outside the lock with an `AbortController` whose signal is aborted on timeout or on the caller's
abort, release the seat and the hold on every failure path, clear the timer and listener, and send the
confirmation as a caught promise that counts failures. Add tests that run calls at once. Update README and
CHANGELOG. Reference solution: `tasks/solutions/hard-seat-holds/`.

## Pattern key

- needed: a per-key lock (mutex) or a per-event queue around each read, wait and write of shared store state.
- needed: a deadline helper that races the charge against a timer and the caller's signal and aborts the charge.
- accepted: a compare-and-set loop on the store in place of the lock.

## Hidden tests (13), cover

200 calls at once on 10 seats, three events at once, one user at once, failed charges under load, a failed charge
one at a time, a charge that never settles, a charge that settles after the timeout, an abort while paying, an
already aborted signal, a rejected and a throwing notifier, sequential ids, unknown event.
