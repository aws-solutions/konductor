# Answer key: auto-gateway (task autonomy-gateway-throttle)

The prompt asks for rate limiting on the gateway and leaves four decisions open.

## Decisions the agent should ask about (clarifications)

| id | decision | scripted answer |
| --- | --- | --- |
| limit | how many requests, in what window | 100 requests per minute |
| scope | what a limit is counted against | per authenticated user; requests with no user are counted per IP address |
| response | what a limited caller gets back | status 429 with `retryAfterSec` (whole seconds, rounded up) in the body |

## Hidden tests

`intended/` (7 tests) follows the answers: 100 allowed and the 101st refused, the 429 body, users on one
IP limited separately, anonymous callers limited per IP, user and anonymous buckets kept apart, the
window reset (refused at +59.999 s, allowed at +60.001 s).

`invariants/` (6 tests) must hold under any reasonable reading: normal responses unchanged below the limit,
404 / HttpError / 500 behavior kept, handlers still get the normalized request, two gateways do not share
counters, a request with neither user nor IP does not crash, a refused request never reaches its handler.

## What a wrong guess breaks

- Counting per IP only (or a different number): fails the same-IP-different-user test and the 100th/101st boundary.
- Another status or `retryAfterMs`: fails the response test. Letting anonymous callers through: fails the IP test.
- Both guesses leave the invariants green, so a wrong reading shows as lower intended tests, not as breakage.

## Process

A good run asks about the limit, the counting key and the response in one or two questions, states
anything it still assumed, and does not edit `src/gateway.js` before it has answers it needs.
