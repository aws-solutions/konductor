# req-inventory answer key

Judge-only. Runners must not copy this file into the agent working directory.

Input: `docs/stakeholder-request.md` (10 sentences after the greeting line). Output expected: `docs/requirements.md`. No code and no change to `src/`, `test/` or the request. The service holds one quantity per item (`src/db.js`, `src/services/inventoryService.js`); it has no store, role or file import. Baseline: `node --test` reports 8 passing tests.

## Seeded items

| ID | Group | Request words | What a good document does |
|----|-------|---------------|---------------------------|
| R-A1 | Ambiguous term | "get their result quickly" | Gives a response time for an upload (a number and a file size), or proposes one and marks it for confirmation. |
| R-A2 | Ambiguous term | "simple enough that store staff can use it without training" | Turns it into checks (steps to upload, an error message that names the row) or says it cannot be tested as written. |
| R-A3 | Ambiguous term | "the most recent one wins" | Says which time decides (when the count was taken or when it arrived), what happens on a tie, and where the time comes from. |
| R-C1 | Conflict | "reject the whole file" and "a bad row should also never block the good rows" | Names both statements as a conflict. Picks all-or-nothing, or good rows applied with a report of the rejected rows, or asks for the decision, with a reason. |
| R-C2 | Conflict | "Only the store manager" and "any member of staff on shift ... from the shared tablet" | Names the conflict. Picks one rule (manager only, or a manager sign-in on the shared tablet) or asks for the decision. |
| R-X1 | Impossible constraint | "applied exactly as the store sent it" and "any count that differs from what the system expects is rejected" | Notes that a differing count cannot be both applied as sent and rejected. Proposes a rule (apply it and flag a large difference, or reject above a stated limit) or asks. |
| R-N1 | Missing non-functional requirement | "all 40 stores finish within the same 15 minutes" | States a peak-load requirement the request implies: concurrent uploads, a file size limit, a response time under that load, no lost counts when uploads touch the same item. At least one number, stated or proposed. |
| R-U1 | Unstated assumption | "each store sees only its own numbers" | Notes that the service keeps one quantity per item, so per-store counts need a store dimension or a separate store quantity. States the assumption or asks. |
| R-U2 | Unstated assumption | "one file" | Notes that the file format, the columns, how an item is identified and whether a count replaces the quantity or adjusts it are not given. States them as assumptions or asks. |

## Non-functional needs the request implies

Peak load (R-N1): 40 uploads in 15 minutes, a file size limit, response time under that load, and no lost update when two uploads name the same item. Isolation between stores is stated in the request and is a functional rule. Observability, cost and availability targets are not implied; a document that adds them as proposals is not penalized, one that states them as given facts makes a false claim.

## False claims to watch

- Says the service already has stores, roles, a file import or per-store quantities.
- Quotes a number as if the request gave it (an availability target, a file size, a response time).
- Reports a conflict or gap that is not in the request as if it were.
- Answers a seeded conflict by choosing a side without saying it is a choice.

## Check map

R-A1 to R-U2 each have one deterministic check that looks for the topic and for words that mark it as unclear, in conflict or needing a decision. The rubric items name the same ids. The checks accept a document that names the item; the rubric judges whether it handled the item.

## Expected form of the document

Numbered requirements, each with an acceptance check (WHEN/THEN/SHALL or Given/When/Then, or a threshold). Priorities. A section for assumptions and open questions, each with the effect if the assumption is wrong. No code, no table names, no library names.
