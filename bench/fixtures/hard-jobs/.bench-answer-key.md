# Answer key: hard-jobs (task hard-batch-flaky)

The 12 visible tests pass on the untouched fixture. The README Behavior section is the contract.

## Seeded defects (all observable through `runBatch` and `createDedupeStore`)

1. Check-then-act race (`src/batch.js`): `dedupe.has(id)` is checked before `await handle(...)` and
   `dedupe.mark(id)` runs after it. Two events with the same id that run at once are both handled and
   both added to the totals. The README rule is deterministic: the first event in input order handles the
   id, later ones are duplicates even when the first fails for good. An in-flight set that is released on
   failure does not satisfy that rule when the first event has already finished and failed.
2. Dedupe expiry (`src/dedupe.js`): `has` ignores the TTL; entries are only pruned inside `mark`, so an id
   is never forgotten until some other id is marked. The pruning also uses `>` while the README says an
   id is forgotten at exactly `ttlMs` (needs `>=`). Fixing the first part exposes the boundary.
3. Retry count (`src/retry.js`): `attempt >= maxRetries - 1` gives `maxRetries` attempts, not `1 + maxRetries`.
4. Shared totals (`src/aggregate.js`): `createAggregator(base = EMPTY)` shares one module-level object, so
   totals leak into the next call and an earlier result changes after the fact. Passes visible tests only
   because they use different customers and the totals test runs first.
5. Config unit (`config/default.json`): `dedupeTtlMs` is 3600; the README says one hour (3600000).

## Traps and distractors

- `docs/OPERATIONS.md` and a comment in `src/pool.js` claim lanes can pick the same index. They cannot
  (`next++` runs synchronously). Changing the pool is wrong; the docs should be corrected.
- `src/legacy/batch-v1.js` is dead code.
- A fix for 1 that marks ids as in flight and never releases them on failure breaks "failed events are
  handled again in a later batch".
- Fixing 4 by only resetting the object in `runBatch` start still leaks if the previous result is mutated.

## Intended resolution

Pre-pass duplicate decision in input order, TTL check in `has` with `>=`, `attempt >= maxRetries`, fresh
aggregator per call, config 3600000, regression tests, CHANGELOG, corrected OPERATIONS.md.
Reference: `tasks/solutions/hard-batch-flaky/`.

## Hidden tests (26)

Totals and cents, call isolation, retry counts and delays, defaults, non-Error rejection, failed order,
concurrency cap and default, option isolation, same-id races, dedupe across batches, ttl boundaries,
failed events not remembered, a seeded noisy batch checked against a model.
