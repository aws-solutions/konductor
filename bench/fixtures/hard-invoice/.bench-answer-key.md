# Answer key: hard-invoice (task hard-invoice-refactor)

The 7 visible tests (4 goldens) pass before and after. The hidden tests check 47 more invoices against the
output of the original renderer, plus the two additions in docs/REPORT.md.

## Behavior that must be preserved (odd on purpose)

- Rounding is `Math.round(x * 10^d) / 10^d`: 1.005 and 3 x 0.335 round down through float error;
  negative half cents round toward +infinity (-0.125 becomes -0.12). Using `toFixed` or round-half-away
  changes output.
- Tax is rounded once on the taxable sum, not per line (the comment above `renderReport` says per line, which
  is wrong).
- Shipping is waived only when the subtotal is strictly above 100; a zero or missing `shipping` hides the row;
  a waived charge prints `free`.
- Descriptions over 28 characters are cut to 25 plus `...` by UTF-16 length, so emoji can be split into a lone
  surrogate; padding uses `.length`, so CJK and emoji misalign. Long skus overflow their column.
- Sorting is by plain string comparison, stable for equal skus.
- Notes wrap at 60 columns; a first word longer than 60 produces a line holding two spaces.
- A missing or unparsable `issuedAt` prints `NaN undefined NaN`; dates are read in UTC.
- Negative zero never prints a sign; unknown currencies print the code and a space; lower case codes are not mapped.

## Traps and distractors

- The comment on `renderReport` is wrong about tax.
- `src/legacy/text-utils.js` is dead code.
- A refactor that "cleans up" the quirks above fails the characterization group for that quirk.
- EUR used to print as `EUR 1,234.56`; the spec changes that on purpose (not part of the preserved set).
