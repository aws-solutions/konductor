# Answer key: hard-exports (task hard-export-formats)

The visible tests (6) pass on the untouched fixture and know only csv and json.

## What the change needs

- TSV as `docs/FORMATS.md` describes it: tab between fields, escapes `\\`, `\t`, `\n`, `\r`, no quoting, empty
  field for a missing value, content type `text/tab-separated-values; charset=utf-8`, extension `.tsv`.
- `listFormats()` exported from `src/index.js`.
- Unknown format errors (library and command line) that name every format.

## Seeded design problem

The formats are listed by name in five places: the `switch` in `src/render.js`, the `if` chain in `src/http.js`,
the `EXTENSIONS` map in `src/filename.js`, the `FORMATS` list and the usage text in `src/cli.js`, and the error
message "expected csv or json" in two files. Adding tsv to each place works and passes the behaviour tests. The
prompt says xml is next, so a change that leaves the list in several files makes every later format touch them
all again.

## Extension step (hidden)

`hidden/extension.test.js` counts the existing source files whose code (comments left out) names every format
`listFormats()` returns. Each such file is edited to add xml. The reference has 1 (`src/formats.js`); adding tsv to
every switch gives 5.

## Traps

- The error messages hard-code "csv or json". Adding tsv without deriving them from the format list leaves them
  wrong.
- TSV is not CSV with tabs: a quoted field is wrong for TSV, the spec escapes instead.
- `docs/CONTRIBUTING.md` asks that the command line and the library accept the same names, which one list gives
  for free.

## Pattern key

- needed: a registry, one table or map from format name to a format object with `contentType`, `extension` and
  `render(rows, columns)`, read by the library, the command line and the error messages.
- needed: strategy objects, each format rendered through the same `render(rows, columns)` contract so the core
  never branches on a format name.
- accepted: one module per format found by listing a directory, in place of the table.
- not needed: a class hierarchy or a plugin loader with configuration; for three formats that is extra abstraction
  (`mod-pattern-fit`).
