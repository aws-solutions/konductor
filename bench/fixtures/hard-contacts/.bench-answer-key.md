# Answer key: hard-contacts (task hard-contacts-rename)

13 visible tests pass before and must pass after, unedited. They use `fullName` everywhere.

## What the visible tests pin (compat traps)

- `test/serialize.test.js` calls `toCsv` with legacy-shaped rows (`fullName` only) and expects the legacy header
  `id,fullName,email,phone`. `exportCsv()` must keep that header; version 2 is opt-in.
- `test/model.test.js` and `test/http.test.js` expect a missing name to fail with `field === 'fullName'`.
  docs/API.md says clients match on `field`, so name errors stay `fullName`. A blind rename to `displayName`
  breaks these tests.

## Documented behavior that the code does not follow (seeded)

1. Stale search index: `src/repo.js` indexes a contact only when first saved, so `update` is invisible to
   `search` (a renamed contact is found by its old name).
2. `list` sorts with `<` on the raw values, so `grace hopper` sorts after `Zed`; docs say case-insensitive.
3. `src/serialize.js` `toJson` returns the stored object, so callers can mutate storage. A naive alias
   (`contact.fullName = ...` on that object) stores a second copy of the name that goes stale.
4. `toCsv` joins fields without quoting; docs require RFC 4180 style quoting.
5. `list({ sort })` with an unknown key silently does nothing; the new spec makes it a `ValidationError` on `sort`.

## Distractors

- Comment in `src/model.js` says the name must be unique (it is not).
- `src/legacy/format.js` is dead code that uses `fullName`.
- `data/seed.json`, `src/cli.js`, README and examples still use the old name and must be updated.

## Intended resolution

`displayName` with a `fullName` alias on input; locale validation; copies from `toJson`; index rebuilt on every
save; case-insensitive list; sort key validation; CSV quoting and version 2; handler `?version=`; docs, README,
examples, seed and CHANGELOG updated. Reference: `tasks/solutions/hard-contacts-rename/`.

## Hidden tests (29)

Output shape, alias input and conflicts, name and locale errors, id use on failure, update paths, alias
freshness, copies, search after update, search order, sort rules, CSV v1/v2/quoting/`toCsv`, handler routes,
seed file.
