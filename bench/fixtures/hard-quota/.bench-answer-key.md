# Answer key: hard-quota (task hard-quota-service)

The visible tests (12) pass on the untouched fixture and say nothing about the new service. The new
service must follow docs/QUOTA-SPEC.md. Several existing modules look reusable but are wrong.

## Seeded defects in existing code

1. `src/window.js` `windowStart` for `day` and `month` uses local-time getters (`getFullYear`,
   `new Date(y, m, d)`), so windows follow the process time zone. Hidden tests run under
   `TZ=America/New_York`; the visible tests run in UTC and cannot see it. Around the March and November
   clock changes a local day is 23 or 25 hours.
2. `src/window.js` `windowEnd` for `month` adds a fixed table of days (`DAYS_IN_MONTH`) that ignores leap
   years, so February 2024 ends a day early. Fixing (1) with `Date.UTC` does not fix this.
3. `src/plans.js` `resolvePlan` returns `Object.assign(DEFAULT_LIMITS, raw)`: it mutates the shared
   defaults, so a plan resolved later inherits limits from an earlier one (`internal` becomes limited
   after `free`). The visible plan tests resolve one plan per process state.
4. `config/plans.json` has `pro.month` 10000; the spec table says 100000.

## Traps and distractors

- `README.md` says windows follow server local time (wrong; the spec says UTC).
- `src/util/dates.js` is dead code with local-time helpers. Not to be used.
- `src/keys.js` `normalizeKey` accepts an empty key and does not apply NFC. The legacy limiter depends on
  accepting an empty key (a visible test pins it), so the quota service needs its own key rule.
- A quota implementation that charges windows one by one charges the minute window of a request that the
  day window then denies (atomicity).
- Request ids stored under `${key}:${id}` collide for key `a:b` id `c` and key `a` id `b:c`.

## Intended resolution

Fix 1-4, add `src/quota.js`, export from `src/index.js`, add tests, update README (UTC, service) and
CHANGELOG. Reference solution: `tasks/solutions/hard-quota-service/` (about 120 changed lines).
