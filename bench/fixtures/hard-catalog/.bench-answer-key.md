# Answer key: hard-catalog (task hard-catalog-limits)

The visible tests (4) pass on the untouched fixture. They make one call at a time on tiny data, so they cannot see
any of the targets in `docs/DESIGN.md`.

## Targets and the mechanism each needs

| target | mechanism | number |
|---|---|---|
| NFR-1 | cache of domain items, least recently used dropped, shared call for one SKU at once | TTL 60 s, 1000 entries |
| NFR-2 | concurrency limit with a queue in arrival order | 4 in flight |
| NFR-3 | retry on `BUSY` and `TIMEOUT` only, then `SUPPLIER_UNAVAILABLE` naming the last code | 3 attempts, 50 ms then 100 ms |
| NFR-4 | index by category built once from the snapshot | 10,000 items |

The numbers are in `config/service.json`. A change that writes them again as literals in code is partial on
`code-nfr-bounded`.

## Seeded defects

1. `src/catalog.js` calls the supplier on every lookup: no cache, no shared call, no limit, no retry.
2. `src/search.js` filters the whole snapshot on every call.
3. The supplier fields (`ITM_NO`, `DESC_TXT`, `PRC_CENTS`, `STAT`, `CAT_CD`) are read in `src/catalog.js`,
   `src/pricing.js` and `src/search.js`, each with its own conversion; `pricing.js` uses `parseInt`, the others
   `Number`.
4. `src/pricing.js` calls the supplier again instead of using the lookup, so a price label bypasses every target.
5. `createCatalogService` accepts `clock` and `sleep` and ignores them.

## Traps

- Retrying inside the concurrency limit (holding a slot while sleeping) still meets NFR-2 but wastes slots; the
  reference retries around the limited call.
- A cache keyed on the legacy record leaks the supplier format into the cache; the design caches domain items.
- `NOT_FOUND` must not be cached and must not be retried.
- Caching the rejected promise of a failed call makes every later lookup of that SKU fail.

## Pattern key

- enterprise: anti-corruption layer at the supplier boundary. One module translates a supplier record into the
  domain item, and no other module reads a supplier field name (`docs/DESIGN.md`, Supplier boundary).
- needed: a cache, a concurrency limit, a retry with back-off and an index, one per target, each bounded by the
  numbers of `config/service.json`.
- not needed: a repository class hierarchy, a generic plugin system or a distributed cache (out of scope).

## Hidden tests (14), cover

domain shape, `NOT_FOUND`, cache hits over 1000 lookups, expiry at 60 s, least recently used eviction at 1000
entries, a shared call for one SKU at once, at most 4 in flight with the limit reached, retry with 50 and 100 ms
waits, `SUPPLIER_UNAVAILABLE` after 3 attempts, no retry on `BAD_REQUEST`, category listing work over 10,000 items,
listing order, price label, and supplier field names read in one module.
