# Refund request feature note

## Summary

Customers can request a refund from the order history area of the web shop. The support team can review the request and approve or decline it. An approved refund returns money to the original payment method.

## Customer path

1. The customer opens an eligible order.
2. The customer chooses the refund action and gives a reason.
3. The customer can see that the request is under review.
4. The customer can later see the decision.

## Staff path

Support staff can inspect the order and record a decision. The order page should show enough context for staff to understand which purchase is being discussed.

## Open detail

The product note does not yet define all eligibility, pricing, approval, notification, or record-keeping details. Those details should be confirmed before test cases are written.
