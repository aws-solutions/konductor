## Extra for this task: a flaky suite

The fixture's suite passes when run plainly but fails now and then. Seed 4 distinct causes of flakiness in the existing tests or helpers (for example: a test that depends on the wall clock or the day boundary, a time zone, a shared temp file or module state that leaks between tests, an unawaited promise or timer, an unseeded random value, an assertion on an ordering that is not guaranteed). The causes must be only in tests, test helpers or in how code is called by tests; a real race in the source is allowed for one of the four, and then the right fix is in the source.

Also write `hidden/stability.test.js` (node:test), at least 6 tests, each of which runs the agent's whole suite once as a child process under one condition and expects exit 0: for example with `TZ` set to a zone far from UTC, with a preloaded script `hidden/chaos/preload.js` (you write it, loaded via `node --require`) that moves the clock to just before midnight or to the last day of a month, with different random seeds read from an environment variable that your preload applies to `Math.random`, with the test files run in reversed order, and with timers slowed. The suite must pass under every condition on the reference solution and must fail under at least one condition on the plain fixture for each of the 4 causes. Keep each suite run under 1.5 seconds. The hidden tests are therefore: your stability tests plus one test per mutant from the mutant kit below. Use the test command `node --test --test-timeout=30000 stability.test.js mutation.test.js` and set `min` to the sum of both counts.

The reference must fix the root causes, not delete or weaken assertions. The mutants guard that: write {{NMUT}} mutants of the source that a sound suite must still kill after the fix, so that deleting tests scores badly.
