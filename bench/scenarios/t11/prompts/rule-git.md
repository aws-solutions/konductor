- The fixture is a git repository with history. Build it with `gen/make-repo.sh`: `git init -b main` inside `fixture/`, then commits made with a fixed identity and fixed dates (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, and the same three `GIT_COMMITTER_*` variables set on every commit; use invented people), with realistic messages and 8 to 30 commits. When it is done, check out the branch the agent starts on, then run `git -C fixture gc -q`, delete `fixture/.git/hooks`, and rename `fixture/.git` to `fixture/dotgit` (the bench renames it back to `.git` when it copies the fixture; git cannot store a `.git` directory). The working tree must be clean (`git status --porcelain` empty) before the rename.
- An answer that needs git work (a merge, a commit) is a directory holding `APPLY.sh`: a POSIX shell script that runs in the repository root (with `.git` restored) and does everything itself, copying any files it needs from `$OVERLAY` (the answer directory). It runs with a fixed git identity already set in the environment.
