# Hand-off: BILL-1187, wrong invoice dates in the CSV export

## The task

Fix the export so `issued_on` and `due_on` are the invoice's UTC date in any server time zone, prove it with a test
that would have caught the bug on our UTC CI, and open a pull request. Month-end close is 2026-11-28; the billing
totals are wrong until this ships.

## What we know

- Reproduce: `TZ=Pacific/Auckland node --test test/export.test.js` fails on the INV-3001 line (shows 2026-11-01, the
  invoice says 2026-10-31). `TZ=UTC node --test test/export.test.js` passes.
- Cause (Sam's diagnosis, 2026-11-18, `docs/notes/sam-diagnosis.md`): `src/format-date.js` `invoiceDate()` uses the
  local-time getters (`getFullYear`, `getMonth`, `getDate`). The billing team wants the UTC date, so the UTC getters
  (`getUTCFullYear`, `getUTCMonth`, `getUTCDate`) are the expected fix.
- Due dates go through the same function, so `due_on` is wrong the same way (INV-3001 due 2026-11-30 shows 2026-12-01).
- CI runs the suite in UTC, which is why the existing test never failed there. CONTRIBUTING.md says CI runs the suite
  twice, `TZ=UTC` and `TZ=Pacific/Auckland`; check the pipeline really does after your change.
- `src/legacy/old-export.js` slices the ISO string and is not affected.
- BILL-842 (PDF footer) is a different service and not part of this work.

## Done when

- `node --test test/` passes with `TZ=UTC` and with `TZ=Pacific/Auckland`.
- A new test fails on the original code even in UTC (for example by running `invoiceDate` under a non-UTC zone in a
  child process, or by checking a timestamp whose local and UTC dates differ in the zone the test sets).
- The pull request names BILL-1187 and shows the before and after export lines for INV-3001.
