# Answer key: t12-split-three-modules

Three independent helpers, each fully specified by its spec in `docs/specs/`. The hidden tests (15) check every rule
of the three specs; the reference is `solutions/t12-split-three-modules`. Slugify and word-stats are plain functions
with no pattern a reviewer should ask for; the key below covers the Roman numerals only.

## Pattern key

- needed: a table-driven numeral conversion in `src/roman.js`: one ordered table of values and symbols (the subtractive
  pairs `CM`, `CD`, `XC`, `XL`, `IX`, `IV` included) that `toRoman` walks from the largest value down, instead of a chain
  of `if` branches per digit.
- needed: `fromRoman` accepts only the standard form by one rule that covers every invalid input: it converts and then
  checks that `toRoman` of the result gives the input back.
- accepted: per-place lookup tables (thousands, hundreds, tens and ones arrays indexed by digit) in place of the one
  ordered table.
- accepted: one anchored regular expression for the standard form (for example
  `^M{0,3}(CM|CD|D?C{0,3})(XC|XL|L?X{0,3})(IX|IV|V?I{0,3})$`) in place of the round trip.
- not needed: a class, a parser object or a lookup cache for the numerals; for this size that is extra abstraction
  (`mod-pattern-fit`).
