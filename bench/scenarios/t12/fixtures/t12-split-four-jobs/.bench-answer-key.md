# Answer key: t12-split-four-jobs

Four independent batch steps, each specified by its doc in `docs/jobs/`, each behind the `run(input)` stub the fixture
gives. The hidden tests (16) check every rule of the four docs; the reference is `solutions/t12-split-four-jobs`. The
request says the steps share no code and no files, so a shared helper module is not expected.

## Pattern key

- needed: each step is a pure `run(input)` function: it reads only its argument and returns its result, with no file
  or console I/O and no state kept between calls, so the scheduler contract the README describes holds for all four.
- needed: fixed-point money in `interest`: the rate is scaled to an integer (hundredths of a percent, or an equivalent
  scale) and the interest is computed and rounded half up in integer arithmetic, never through a floating-point product.
- needed: calendar dates as day numbers in `dormant` and `late-fee`: each ISO date becomes one integer day count
  (`Date.UTC(...) / 86400000` or an equivalent), and every window and lateness rule compares those integers.
- accepted: `BigInt`, or plain integers when the products stay below `Number.MAX_SAFE_INTEGER`, for the fixed-point sum.
- accepted: a day count from a civil-date formula (a Julian day number) in place of `Date.UTC`.
- accepted: a small date or money helper defined inside each step's own module (the steps share no files).
- not needed: a shared job base class, a job registry, a scheduler or a plugin loader; the scheduler is outside this
  repository (`mod-pattern-fit`).
