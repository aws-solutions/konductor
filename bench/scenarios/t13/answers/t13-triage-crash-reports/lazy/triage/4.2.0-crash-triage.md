# 4.2.0 crash triage

**Audience:** desktop release owner  
**Scope:** reports collected after the 2026-03-16 4.2.0 release, with older and beta records kept only for comparison.

## Decision

There are four current-release defect groups. Two need a hotfix before Friday: the removable-volume sync crash and the Linux thumbnail-cache memory failure. The tray crash is an existing macOS defect rather than a 4.2.0 regression. The local database crash affects very few users and should go to the next release.

## Defect tickets

### Ticket A: removable-volume sync root

This group has 119 reports from 84 users: 71 Windows reports and 48 macOS reports. It is new in 4.2.0. Windows reports alternate between `SyncRoot::resolve` and `SyncRoot::resolveImpl`; the collector notes that these closely related frames can be one underlying group, so I did not split them. The failure is a null path while resolving a removable sync root after the volume is unavailable.

The most likely suspect is the new `src/sync/root.cpp` `SyncRoot::resolve` change. The diff adds removable-volume path selection and normalization at `release/4.2.0-diff.txt:115-119`; the operational grouping also records a removable-volume path lookup at `ops/logs/desktop-sync.log:252`. The retry scheduler change is not a match for the crashing frames, so it is not the cause of this group.

**Action:** hotfix before Friday. At about 9,0 weekly active users, 84 affected users are above the policy's 1% trigger. The colleague confirmed that the removable-drive feature has a server-side flag, so we can disable it for everyone within an hour. The hotfix cannot ship only on one platform: the colleague confirmed that it ships on all platforms together.

### Ticket B: macOS tray refresh

This group has 42 reports from 39 users, all on macOS. It is not a 4.2.0 regression: 11 matching reports are present in 4.1.3, including `crashes/crash-0216.json:1`. The defining frames are `TrayIcon::refresh` and its tray-update callers.

**Action:** next release. Track the existing defect and avoid attributing it to the 4.2.0 source diff.
