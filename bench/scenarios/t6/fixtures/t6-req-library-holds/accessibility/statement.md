# County Library Service - Digital Accessibility Statement

## Commitment
The County Library Service is committed to ensuring digital accessibility for people with disabilities. All new digital services, including the online holds system, must meet WCAG 2.1 Level AA standards.

## Standards Compliance
- **Primary standard**: WCAG 2.1 Level AA
- **Secondary standard**: Section 508 (U.S. Federal)
- **Applicability**: All public-facing web interfaces, mobile apps, and staff tools

## Required Features

### 1. Perceivable
- Text alternatives for non-text content
- Captions and transcripts for multimedia
- Content that can be presented in different ways without losing information
- Easy-to-see and hear content

### 2. Operable
- Keyboard accessibility for all functions
- Enough time to read and use content
- Content that does not cause seizures or physical reactions
- Clear navigation and findable content

### 3. Understandable
- Readable and predictable text and operation
- Input assistance for forms and controls
- Clear error identification and recovery

### 4. Robust
- Compatibility with current and future user tools
- Valid markup for assistive technologies

## Specific Requirements for Holds System

### Screen Reader Compatibility
- Must work with JAWS, NVDA, and VoiceOver
- ARIA labels for all interactive elements
- Logical reading order
- Meaningful link text

### Keyboard Navigation
- All functions accessible via keyboard
- Visible focus indicators
- Skip navigation links
- Logical tab order

### Visual Design
- Color contrast ratio of at least 4.5:1 for normal text
- Text resize up to 200% without loss of functionality
- No information conveyed by color alone
- Flexible layouts that work at different zoom levels

### Forms and Input
- Clear labels for all form fields
- Error messages that identify the field and describe the error
- Suggestions for correcting errors
- Timeout warnings for lengthy processes

### Mobile Accessibility
- Touch targets at least 44x44 pixels
- Support for system text size settings
- Landscape and portrait orientation support
- Avoidance of gestures that require fine motor control

## Testing Protocol
1. Automated testing using axe-core or similar tools
2. Manual keyboard testing
3. Screen reader testing with actual users
4. Color contrast verification
5. Mobile device testing

## Exceptions
- Third-party content not under library control
- Archived materials (pre-2020 digitization)
- Highly specialized tools with equivalent alternative access

## Timeline
- Design phase: Accessibility review required
- Development: Continuous accessibility testing
- Pre-launch: Full accessibility audit
- Post-launch: Quarterly reviews and updates
